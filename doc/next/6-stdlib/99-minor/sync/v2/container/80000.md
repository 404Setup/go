The new [sync/v2/container] package provides four generic maps with ordered iteration:

- [OrderedMap] is a concurrent map whose iteration follows insertion order.
  Updating an existing key preserves its position. [OrderedMap.Shrink] reclaims
  storage retained by deleted entries while preserving insertion order.
- [ConcurrentSkipListMap] is a concurrent sorted map using a randomized skip
  list. Loads and ascending iteration do not acquire locks; writes and boundary
  queries use a mutex. Iteration is weakly consistent and permits reentrant
  callbacks. Reverse iteration takes expected O(n log n) time.
- [LinkedHashMap] maintains insertion order or, when constructed with access
  order enabled, least-to-most-recent access order. [LinkedHashMap.Peek] reads
  without changing that order, and [LinkedHashMap.PollFirst] removes the oldest
  entry. Deleted entries are immediately unlinked.
- [TreeMap] is a sorted red-black tree with O(log n) lookups, updates, deletes,
  and boundary queries.

[NewTreeMap] and [NewConcurrentSkipListMap] require a comparison function, such
as [cmp.Compare]. Comparator-equal keys identify one entry. Both maps provide
`First`, `Last`, `Floor`, `Ceiling`, `Lower`, `Higher`, and a half-open
`RangeBetween(lower, upper)` iterator, as well as removal of either endpoint.
Nil values are supported when the value type permits them.

`LinkedHashMap` and `TreeMap` require external synchronization when used
concurrently with writes. Their iterators panic if iteration continues after
entries are added, removed, or reordered. `OrderedMap` and
`ConcurrentSkipListMap` permit concurrent reads and writes.
